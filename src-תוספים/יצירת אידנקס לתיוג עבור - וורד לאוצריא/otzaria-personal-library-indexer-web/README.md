זו גרסת דפדפן (ממשק חזותי) לכלי סריקת הספרייה האישית של אוצריא. הלוגיקה הפנימית זהה לכלי המקורי בשורת הפקודה (otzaria-personal-library-indexer) - אותה סריקה, אותה הוספת סימניות לכותרות ב-Word, אותה בנייה של מסמך-מלווה וקובץ קישורים לכל PDF עם תוכן עניינים - רק שבמקום להריץ פקודה בשורת הפקודה ולהקליד תשובות של מ/ה/ד, פותחים דף אחד בדפדפן ולוחצים על כפתורים.

איך מריצים: בתוך תיקיית הכלי הזה מריצים פעם אחת npm install, ואז בכל פעם שרוצים להשתמש בכלי מריצים npm start. הפקודה בונה את הקוד, מפעילה שרת מקומי על המחשב עצמו (לא פונה לאינטרנט), ופותחת אוטומטית את הדפדפן בכתובת http://localhost:4173. אם הדפדפן לא נפתח לבד, אפשר להקליד את הכתובת הזו ידנית. את השרת עוצרים עם Ctrl+C בחלון שבו הוא רץ.

בדף עצמו: קודם בוחרים תיקייה - אם לוחצים על "בחר תיקייה..." נפתח חלון בחירת תיקייה רגיל של Windows (בדיוק כמו בכל תוכנה אחרת), ואפשר גם פשוט להקליד את הנתיב בתיבת הטקסט. מתחת לבחירת התיקייה יש תיבת טקסט נוספת בשם "תיקיית פלט", מלאה מראש בשם "_אינדקס_אישי" - זו התיקייה שתיווצר בשורש התיקייה שנבחרה, ושבתוכה יישמרו כל הקבצים שהכלי מייצר. אפשר להשאיר את השם המוצע כמות שהוא (המומלץ), או להקליד שם אחר אם רוצים תיקיית פלט בשם שונה. אחרי שהתיקייה נבחרה לוחצים על "התחל סריקה", ובתיבת ההתקדמות מופיעות בזמן אמת כל הפעולות: אילו קבצים נמצאים, מה קורה בכל אחד מהם, אילו מסמכים-מלווים נבנים לקבצי PDF וכו'.

חשוב להבין את השינוי המרכזי בהתנהגות: הכלי לא כותב יותר את המסמך-המלווה, את קובץ הקישורים שלו, ואת קובץ המיפוי personal-library-index.json ליד קבצי המקור עצמם. כל הקבצים האלה נשמרים יחד בתיקייה אחת ("_אינדקס_אישי" כברירת מחדל) שנוצרת בשורש התיקייה שנבחרה לסריקה - ולא בכל תת-תיקייה שבה נמצא PDF - כדי לא ללכלך את תיקיות הספרים האמיתיות. מכיוון שכעת כמה תת-תיקיות מקור עשויות "לחלוק" תיקיית פלט אחת, אם נמצאים שני קבצי PDF באותו שם בתת-תיקיות שונות (למשל sample.pdf בשתי תיקיות שונות), הכלי מוסיף אוטומטית לשם המסמך-המלווה של הקובץ שאינו בשורש קידומת של הנתיב היחסי שלו (למשל "נושא1_sample - אינדקס.docx"), כדי שהשמות לא יתנגשו. הנתיב האמיתי של קובץ ה-PDF המקורי ממשיך להירשם כרגיל בתוך קובץ המיפוי, רק מיקום הקבצים שהכלי עצמו יוצר השתנה.

אם הכלי נתקל בקובץ Word עם כותרות בלי סימנייה, הסריקה עוצרת ונפתחת בדף חלונית שאלה עם שלושה כפתורים: "הוסף למקור" (משנה את הקובץ המקורי במקום), "העתק לקובץ חדש" (יוצר עותק בשם עם התוספת "עם סימניות" ומשנה רק אותו), ו"דלג" (לא נוגע בקובץ הפעם - אפשר לחזור אליו בהרצה הבאה). הסריקה ממשיכה אוטומטית ברגע שלוחצים על אחד הכפתורים, ואם יש כמה קבצים כאלה ברצף, כל אחד מהם מקבל חלונית נפרדת בתורו.

בסיום הסריקה מוצג בדף סיכום ברור: כמה קבצים נסרקו, אילו ספרים נוספו או עודכנו (Word או מסמך-מלווה ל-PDF) עם מספר הכותרות של כל אחד, ואילו קבצים דולגו או לא נתמכו ולמה. יש גם כפתור שפותח בסייר הקבצים של Windows את תיקיית "_אינדקס_אישי" (או השם האחר שהוקלד) שבתוכה נשמר קובץ personal-library-index.json יחד עם כל המסמכים-המלווים וקובצי הקישורים, ואפשרות (בקישור "הצג JSON גולמי") לראות את תוכן הקובץ המלא אם רוצים לבדוק פרטים.

הערה טכנית: בחירת התיקייה מהדפדפן מבוססת על כך שהשרת מריץ ברקע סקריפט PowerShell קטן שפותח את חלון בחירת התיקייה המובנה של Windows ומחזיר את הנתיב שנבחר - זה עובד רק במחשב Windows מקומי (בדיוק כמו שהכלי הזה מיועד לשימוש), ולכן אין תמיכה בהרצה מרוחקת או מדפדפן שאינו רץ על אותו מחשב שבו נמצא השרת.

לבדיקה עצמית (למפתחים בלבד, לא נדרש לשימוש רגיל): npm run verify מייצר קבצי דוגמה (fixtures), מריץ סריקה מלאה דרך ה-API של השרת בדיוק כפי שהדפדפן היה עושה, עונה אוטומטית על שאלות הסימניות, ומוודא שהתוצאה תואמת את הצפוי.
